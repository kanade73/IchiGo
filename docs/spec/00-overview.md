# IchiGo 実装仕様 v1.2

作成: 2026-09-08。優先順位: 本文の必須仕様 > 各チケット > 参考実装。
本仕様の数値設定は初期実験値であり、速度・棋力・所要時間の実測値ではない。

## 1. ユーザー合意と設計判断

- Mac 上で推論・探索・CGOS 対局する。端末は Apple M5、10 CPU cores、32GB、macOS 26.3.1(a)、Swift 6.2.3 と確認した。
- 学習には大学の A4000 複数枚を使える。型番詳細、VRAM、台数、接続、CUDA 環境は未確認。実装時 doctor が検出し、1/2/4枚でのDDPを正式対応とし、まず単一サーバー4枚を検収する。複数サーバー間の通信は初期検収範囲外。
- 最初の対外目標は9路CGOSでの実対局とする。19路への拡張を保つ設計・形状テストは初期から行い、19路の本学習・棋力検収は9路CGOS出場後の段階とする。
- 本体は学習可能な2入力16種類の論理ゲート。学習時の連続緩和、推論時の真理値表への固定を採用する。浮動小数点の出力ヘッドを許容する。
- policy、勝ち/引分/負け、目差、ownership を初期版から学習する。勝率・目差・読み筋を CGOS へ渡す。
- 教師・棋譜の利用制限なし。RinGo既存9路データの照合可能なラベルを優先して蒸留し、不足分だけ教師を実行する。その後自己対局と再ラベル付けで改善する。
- RinGo の自作コードのコピー・変更は許可済み。参照先は編集せず、本プロジェクトへ必要なものを移植する。
- GUI は作らない。CLI、GTP、CGOS クライアント接続を提供する。

## 2. 技術構成

| 領域 | 採用 | 理由 |
|---|---|---|
| 囲碁ルール・探索・GTP | Swift、RinGo から移植 | 既存テストと探索を活用 |
| 正解となる離散推論 | Swift UInt8 スカラー | Metal を使わず全ゲートを検証可能 |
| 高速推論 | Metal uint32 ビット演算 + FP32 ヘッド | Mac で CUDA 依存なく実行 |
| CPU 最適化 | Swift UInt32 バッチパック | 小バッチの比較対象、GPU 障害時の選択肢 |
| 学習 | Python / PyTorch / CUDA | A4000 を利用、CPU 上で小規模テスト可能 |
| 教師 | 外部 KataGo analysis process | 学習用ラベル生成を独立させる |
| モデル受け渡し | JSON manifest + little-endian raw tensors | Python と Swift の明示的契約 |
| 実験記録 | JSON + CSV + SGF | サービスへの依存を増やさない |

Mac 実行環境に PyTorch、CUDA、MLX を必須にしない。学習コードの Mac CPU 動作は単体テスト・小規模試験用であり、Mac GPU 学習の別実装は v1 に入れない。MLX は教師用 RinGo を外部実行する場合だけ別途必要になる。

## 3. 構成と依存方向

```text
Sources/IchiGoCore       ← RinGoCore のルール一式
Sources/IchiGoFeatures   → IchiGoCore
Sources/LogicModel       → Foundation (モデル検証、CPU、ヘッド)
Sources/LogicMetal      → LogicModel, Metal (Resources/*.metal)
Sources/IchiGoEngine    → Core, Features, LogicModel (評価 protocol、探索)
Sources/IchiGoGTP       → Engine (GTP 状態機械、analysis)
Sources/ichigo          → 上記 (CLI と実行時 backend 選択)
Training/ichigo_train   → torch, numpy (Swift には依存しない)
Scripts/               → CLI を subprocess として利用
Tests/                 ← 小さな固定 fixture、教師参照 fixture
configs/               ← モデル、学習、CGOS の公開設定例
```

`LogicMetal` を除いたテストは Metal デバイス不要。Linux 全体ビルドは必須にしないが、Python 学習は Linux 対応必須。SwiftPM tools 6.0、検証 toolchain 6.2.3、deployment target macOS 14 を初期値とし、実際の下限互換は別端末がなければ未検証と記載する。

## 4. 研究方式と最初から入れる棋力上の要素

DLGN の連続緩和を使い、囲碁向けに空間共有・局所接続・遠距離接続・履歴・合法手・グローバル集約を追加した独自構成とする。論文の画像分類ネットをそのまま移植するものではない。基本方式の根拠は [DLGN 論文](https://arxiv.org/abs/2210.08277)、空間共有と残差的初期化の参考は [Convolutional DLGN](https://arxiv.org/abs/2411.04732)。囲碁への有効性はこれらの研究からは保証されない。

早期に採用するもの: 全局面の合法性と履歴、盤サイズに依存しない局所重み、D4 データ拡張、複数目的蒸留、盤全体の統計を使う policy/value head、離散モデルでの選抜、PUCT、木の再利用、推論バッチ化、同時間対局による比較。

後続実験: ownership/終局ラベル改善、局面の再ラベル付け、接続の再探索、幅の拡大、ゲート簡約、CUDA fused training kernel、自己対局 RL。19路が弱い場合は9路を動作可能のまま保持し、19路の教師誤差・長距離問題・探索速度を切り分ける。19路を黙って範囲から外さない。

## 5. マイルストーン

| 段階 | 完了条件 | 棋力上の意味 |
|---|---|---|
| M0 数値基盤 | 16ゲート、特徴、モデル往復、CPU 推論の一致 | 棋力主張なし |
| M1 学習する9路 | 固定小データ過学習、蒸留モデル輸出、9路対局完走 | ランダム着手より改善を確認 |
| M2a 9路CGOS準備 | 9路hardモデル、4GPU学習検収、Mac推論parity、時計・解析、ローカルCGOS完走 | 実接続可能なパッケージ |
| M2b 9路CGOS出場（当面の目標） | 接続先・アカウント設定後、公開9路CGOSで20局完了、解析値の受け渡し確認 | 対外動作実績を得る |
| M2c 19路拡張 | 19路学習・対局検収、両サイズの運用確認 | 19路へ展開 |
| M3 棋力改善 | 同時間対局で旧版より有意に改善、校正・失着分析 | 強化が再現可能 |
| M4 継続学習 | 自己対局→再学習→検証→手動選抜まで自動化 | 反復改善可能 |

M3の9路棋力改善はM2b直後から開始し、M2cの完了を待たない。Metalの速度目標未達だけで出場を止めず、時計・完走条件を満たす検証済みbackendを採用する。

M1 の時点で19路のランダムモデルによる形状・ルール・GTP テストも行う。学習データは盤サイズ別、初期 champion も9路用と19路用を分ける。共同重みは後続比較で採用する。

## 6. 実装担当の進め方

1. [04-tasks](04-tasks.md) の未完了チケットを依存順に選ぶ。
2. 指定された型・形状・失敗動作を実装する。推測で意味を変更しない。
3. チケットの検収だけをまず実行し、対応する完了ゲートを通す。
4. `docs/implementation-status.md` にチケット、変更、実行コマンド、結果、制約を追記する。
5. テスト未実行は未実行と書く。ランダムモデルの完走を学習成功や棋力達成と扱わない。

真理値表、座標、勝率視点、フォーマットの変更は仕様・Python・Swift・fixture を同じチケットで変更する。学習パラメータの改善は設定差分と評価結果を保存すればよく、別の承認待ちを設けない。
